### 4.5 标题命名规范(先标题后内容 + 去AI化)

**构思顺序**: 先根据题目和一级标题构思全部二级标题,再构思三级标题,**标题全部锁定后才深化写内容**。

**紧扣原则**:
- 二级标题紧扣一级标题(能回答"它是这个一级标题的哪个侧面")
- 三级标题紧扣二级标题(能回答"它支撑二级标题的哪个要点")
- 答不上来即偏题,需改或删

**命名规范**(参考原始文件):
- **创新点**: `{序号}. {创新方向简述}`,如"1. 体卫融合的政策协同机制"
- **研究方向**: `{序号}. {方向主题}`,如"2. 运动处方与运动康复的干预机制"
- **关键问题**: `{序号}. {问题的核心矛盾}`,如"3. 基层运动健康服务的递送机制"

**标题字数(2026-08-14)**:
- 三级标题(自己构思的)字数在 **5-15 字之间**,根据内容实际情况调整
- **不要都太短**(如全都 6-8 字),也不要都太长,信息量要均衡
- 示例: 10-14 字为宜,既能点明内涵又不啰嗦

**避免的标题模板**:
- ❌ "X机制:从A到B"模式(如"政策协同机制:从顶层设计到地方落地")— 模板化
- ❌ "创新点一/二/三""研究内容一/二"— 机械编号无内涵
- ❌ "1. 具有重要意义的研究""2. 关于XX问题的探讨"— 空话套话

**标题去AI化(避免模板化)**:
- ❌ 禁用:"创新点一/二/三""研究内容一/二""具有重要意义的研究"等机械编号+泛化命名
- ✅ 要求: 每个标题根据实际内容命名,有具体内涵
- **风格**: 官方正式、书面化(不用口语大白话),但避免"赋能/抓手/闭环/范式"等 AI 味滥用词
- 字数: 10-20字,精炼,一看标题就知道这节讲什么

### 分点段落加粗规则(2026-08-13)

对于"1. 小标题:描述"或"(1) 小标题:描述"这种**分点段落**(常见于"学校提供条件""预期成果"等章节):
- **编号 + 小标题 + 冒号** 部分 → **加粗**(突出条目的"分点标题")
- **冒号后的描述文字** → 不加粗(正常正文)
- 整个段落仍按正文格式(首行缩进2字符 + 1.5倍行距)

示例:
- "1. **项目资金支持**:学校设立大创专项经费..."(加粗部分是"1. 项目资金支持:")

### 图片插入规范(2026-08-14)

> 正文生成后,按参考文件的方式在正文中穿插插入图片,紧跟相关论述,不破坏格式。

**图片数量(硬性要求)**:
- 一篇文章内图片**不得少于 5 张**,一般在 **10 张左右**,根据项目需求确定
- 不足 5 张视为不合格

**穿插位置**(紧跟相关论述,不堆文末):
- 项目简介之后 → 政策文件/背景相关图
- 研究背景/研究现状之后 → 关系图/框架图
- 研究内容之后 → 模式图/示意图
- 技术路线之后 → 技术路线图

**图片类型清单**(根据项目需求选用):
- 政策概念图、项目计划图、流程图、概念图、市场数据展示图、重要数据展示图、产品设计图、关系图/框架图/模式图/技术路线图

**图片内容分析(生成前必做)**:
- 每张图先判断"文字密度"定位: 文字配图的介绍图(政策/路线/流程→文字多)、数据图表(数据为主)、产品的展示图(产品/系统→文字少)
- 文字配图 → 文字多清晰; 产品展示 → 文字少突出外观

**穿插密度(第一原则:根据内容来)**:
- 根据内容需要配图,不为了凑数量硬插
- 不要过于密集,让图分散在正文中
- 允许两张左右图片比较接近(相邻),但不超过连续3张

**插入格式**:
- 图片**独占一个段落**
- 图片下方紧跟**图注段落**: `图N + 说明`,居中
- 图片宽度约 **11cm**(适中,不占满版),高度按比例自适应
- 图注字体: 宋体小五(10.5pt),居中

**图注编号规则(按物理顺序)**:
- 图片编号按**正文中出现顺序**从 1 开始连续编号,不分章节独立计数
- 全文第一张出现的图是"图1",依次往后,最后一张是"图N"
- 编号顺序 = 图片在文档中的物理前后顺序,不是生成顺序

**生成方式(生图渠道) — 默认 AI绘图,缺失时提醒**:
- **默认启用 `AI绘图` skill(即 nano-banana-pro,基于 Gemini 3 Pro Image)**
- 调用: `uv run {baseDir}/scripts/generate_image.py --prompt "..." --filename "..." --resolution 1K|2K|4K`
- 工作流: 1K 草稿 → 微调迭代 → 4K 定稿
- **缺失/调整时提醒用户**:
  - 未检测到 AI绘图 skill 或 API key → 主动提醒用户提供生图渠道(API key / 本地工具 / 其他接入)
  - AI绘图 skill 被调整或更换渠道 → 记录新渠道,后续按新渠道执行
- **除非用户手动调整,否则一直默认使用 AI绘图 skill**

**图片类型分工(生成方式)**:
- 所有图片默认用 AI绘图 skill 生成
- 关系图/框架图/模式图/技术路线图/流程图(文字精确) → 若 AI绘图 文字效果不佳,可退回代码/SVG
- 概念示意图/产品设计图/数据图 → AI绘图 文生图

**插入实现要点**:
- 用 `insert_paragraph_before` 在目标段后插入时,**先插图片段落、再插图注段落**,才能保证图片在上、图注在下(反之会颠倒)
- 图片插入后按物理顺序重编图注序号

**不得破坏格式**: 插入图片和图注时,沿用正文段落格式(首行缩进、行距),不改动母版边框、表格结构。

### 总字数要求(2026-08-14 严格把控)

- **目标**: 12,000 字(含符号)
- **范围**: 8,000-20,000 字
- **底线**: 实际填充正文(**扣除 ❓未填字段**)至少 **8,000 字以上**,低于 8k 即视为字数不足,必须扩充
- **不要少于需求字数太多**: 用户要 1 万字时,正文实填应稳定在 9,000-10,000 字,不能只写 7,000-8,000 字
- 生成后检查总字数,不足 8,000 字必须扩充
- 研究进度安排: 200-400字(可调,不是硬性要求)
