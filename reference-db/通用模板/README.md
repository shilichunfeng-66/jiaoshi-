# 通用模板 — 模块说明

> 本模块是**学校/项目类型未入库时的兜底方案**。当用户需求的类型不在 `schools/` 或 `project-types/` 库里时，或用户在项目类型确认时选「**其他**」，启用本模块。

## 定位

| 场景 | 处理 |
|------|------|
| 学校/类型已入库 | 用对应专属模块 |
| 学校/类型未入库 | 启用本通用模板，格式要素**动态获取** |

## 完整启用流程（六步，2026-08-15 用户要求）

### 第一步 · 启用确认
检测到用户需求的类型未入库 → 提示启用通用模板 → **询问用户确认**

### 第二步 · 确认项目类型 + 获取官方文件
- 向用户确认项目类型
- 让用户发**官方文件**（申报书模板、申报通知、格式要求等）

### 第三步 · 底板确认流程（核心 — 2026-08-29 升级，「其他」类型重点环节）

> 目标：确保最终拿到一个**格式正确的执行魔板**。完整规则以 orchestrator「通用模板处理规则·第三步」为准，此处为速记版。

- **3.1 底层魔板判定（先问用户）**：拿到文件先问"是否为可直接使用的底层魔板（空白格式化文件）？"
  - 是 → 直接当母版用，提取格式要素，跳到第四步
  - 否/不确定 → 进入 3.2；文件里没有可用底板 → 再问一次是否有官方格式文件可补充
- **3.2 文件框架解读**：按「框架解读清单（第一轮设定，8 组）」逐项读取——A1 文件总体 / A2 表格结构 / A3 章节结构 / A4 字体字号 / A5 页面设置 / A6 格式硬约束 / A7 字段盘点 / A8 特殊注意事项（明细见 orchestrator 3.2）。输出框架解读清单，**问用户哪些部分保留**（保留 = 格式所需），基于保留要素组装**执行魔板**（空白底稿，清除示例内容），并生成对应 format.md
- **3.3 多轮格式校验（至少 2 轮）**：①结构自检（与保留清单逐项比对）②格式自检（与原文件实测值逐区域核对）；每轮结果给用户看，疑问主动问；两轮通过后执行魔板交用户**最终确认**，有修改再校验一轮，通过前不得开始生成
- **3.4 兜底规则（2026-09-11 更新）**：无任何可用文件 → 纯文字生成；**无字体字号要求 → 用默认格式 `默认格式-字体间距标题.md`（源：池州学院大创，仿宋体系）**

> **「其他」类型功能边界**：除第三步底板确认外，其余环节与通用模板完全一致，暂不新增功能。

### 第四步 · 章节思考环节（单独进行）
- 分析官方文件和用户需求，构思章节
- 官方明确章节 → 按文件；未明确 → **6 个章节左右**
- 重点写：项目意义 / 目的 / 研究内容 / 研究方案 / 执行方案 / 项目简介
- 学校意见、二级学院意见、导师意见、经费预算 → **官方没要求就不写**（非必须）
- 写出章节类型 → **对用户确认一次**

### 第五步 · 后续流程（与大创一致）
确认章节后：确认题目 → 博士水准分析 → 标题构思 → 生成 → 去AI味 → 字数把控

### 第六步 · 图片（询问用户）
主动询问用户是否需要配图


## 关键要点速记

- **底板确认优先**：先问"是否可直接用作底层魔板"；不能直接用 → 框架解读 → 保留确认 → ≥2轮校验 → 执行魔板用户确认后才生成
- **字体兜底（2026-09-11 改）**：官方文件无字体字号要求时，用**默认格式**（`默认格式-字体间距标题.md`，源：池州学院大创·仿宋体系）
- **章节兜底**：官方无章节要求时，6 章左右，意见/经费等非必须部分不写
- **纯文字生成**：不依赖母版 docx（除非用户提供了母版，则基于母版）
- **每次都有确认环节**：启用确认、底板判定、章节确认、执行魔板确认、图片询问
