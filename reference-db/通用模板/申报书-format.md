# 通用申报书 — 格式规范（学校/类型未入库时兜底）

> 本规范用于学校/项目类型未入库时的兜底生成。格式要素**动态获取**：官方文件优先，其次询问用户，最后用兜底默认值。

## 1. 格式要素获取顺序

| 要素 | 优先级 |
|------|--------|
| 官方文件（用户提供的母版/申报书模板/通知） | ① 从文件中提取 |
| 询问用户 | ② 主动提问 |
| 兜底默认值（见下） | ③ 用户不指定时 |

## 2. 字体字号（兜底：阜阳师范大学标准）

> **官方文件无字体字号要求时，采用阜阳师范大学的字号和字体。**

| 元素 | 字体 | 字号 | 其他 |
|------|------|------|------|
| 正文 | 宋体 | 小四(12pt) | 1.5倍行距 |
| 一级标题 | 黑体 | 四号(14pt) | 加粗 |
| 二级标题 | 宋体 | 小四(12pt) | 加粗 |
| 三级标题 | 宋体 | 小四(12pt) | 加粗 |
| 封面表字段 | 宋体 | 四号(14pt) | — |
| 西文 | Times New Roman | 同对应中文 | — |

**段落格式**: 段前6磅 / 段后6磅 / 首行缩进2字符 / 1.5倍行距

## 3. 章节结构（兜底：6 章左右）

> **官方文件未明确章节时，控制在 6 个章节左右。**

| 序号 | 章节名称 | 字数 | 说明 |
|------|---------|------|------|
| 一 | 项目简介 | 800-1200字 | 项目概述 |
| 二 | 项目实施的目的、意义 | 1500-2000字 | 为什么做 |
| 三 | 项目研究内容 | 2000-2500字 | 做什么 |
| 四 | 项目研究方案 | 1500-2000字 | 怎么做（方法+技术路线） |
| 五 | 项目执行方案 | 1000-1500字 | 进度安排+实施步骤 |
| 六 | 预期成果 | 300-500字 | 成果清单 |

**非必须部分（官方没要求就不写）**：
- 学校意见、二级学院意见、导师意见（签字栏）
- 经费预算（官方有预算要求时才写）

> 重点放在：项目意义 / 目的 / 研究内容 / 研究方案 / 执行方案 / 项目简介。

## 4. 封面与基本信息（纯文字生成，或基于用户母版）

- 若用户提供了母版 → 基于母版，封面字段按母版
- 若纯文字生成 → 封面采用表格：项目编号 / 学校名称 / 项目类型 / 项目名称 / 负责人 / 团队 / 指导教师 / 学院专业 / 申报日期

## 5. 信息分类矩阵

| 类别 | 处理方式 |
|------|---------|
| ❓ 未知·必须索取 | 学校/学院/负责人/成员/指导教师/日期 → 询问，未提供留空 |
| 🔶 已知·需确认 | 项目类型、关键词、经费明细、预期成果 → 生成建议后确认 |
| ✅ 已知·自动生成 | 学校名（如已知）、正文各章节 → 直接生成 |

## 6. 字数要求（通用默认）

- 整体正文约 **1 万字**（用户指定则以用户为准）
- 重点章节深度拓展，不强行凑数
- 生成后检查字数，不足必须扩充

## 7. 通用规则（与学校模块一致，自动继承）

- **标题命名**：先标题后内容，二级扣一级、三级扣二级，去AI化（5-15字，有具体内涵）
- **标题格式**：一级四号加粗、二三级小四加粗、缩进2字符、1.5倍行距
- **分点段落加粗**：编号+小标题加粗，描述不加粗
- **去AI味**：默认启用 humanizer（中文科研申报书适配版），嵌入生成同步处理
- **引号规则**：中文弯引号("")，1万字文章≤30对，一段≤1-2对，只给特定称谓加引号
- **图片**：主动询问用户是否配图，不默认；配图时 AI绘图默认生图，缺失时提醒

## 8. 章节思考环节（单独进行，不可跳过）

生成前，单独执行章节思考：

1. 分析官方文件和用户需求
2. 构思章节类型（官方明确 → 按文件；未明确 → 6 章左右）
3. 判断非必须部分（意见/经费）是否保留
4. 写出章节类型清单 → **对用户确认一次**

## 9. 生成方式

- 用户提供了母版 → 基于母版撰写
- 无母版 → 纯文字生成全新 docx（封面表 + 正文）
- 生成后按通用格式规范应用标题层级格式
