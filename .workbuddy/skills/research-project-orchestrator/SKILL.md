# 科研项目文档生成 — 主调度

## 🚫 反造假铁律(最高优先级 · 2026-09-03 用户硬性要求 · 一切生成必须遵守)

> **数据不能造假、文献不能造假、信息不能造假。只允许使用能找到、真实存在的文件和信息。**

1. **数据不造假**：不得编造任何统计数据/调研数据/性能参数/增长率/金额/比例。只有能确认真实来源(用户提供文件、可查证网页/文献/官方通知)时才写具体数字，且随文标注来源；无法确认的一律定性表述(如"据调研""有所提升")，绝不伪造精确数字。
2. **文献不造假**：不得虚构论文/专著/作者/期刊/年份/DOI。只引用真实存在(或来自用户提供的参考资料)的文献；不确定时改为"相关研究显示"等不指名表述，禁止"某学者(20xx)指出"式编造。
3. **信息不造假**：申报人/单位/指导教师/姓名学号电话等一律来自用户输入，❓字段必须询问，缺失留空，绝不代填猜测。
4. **出处原则**：可查证事实/数字/成果必须基于用户提供文件(母版/参考申报书/论文)、项目真实设定、或有把握的常识。不确定的宁可空着/定性，绝不编造。
5. **违规后果**：一旦发现任何编造(假数据/假文献/假信息)，该轮产出作废并全流程返工；此铁律优先于任何"让内容更丰满/字数达标"的指令。

> 本铁律在**每一轮生成**开始时向模型重申；工作台端已在模型调用统一入口(`_model_chat`)自动注入，skill 执行时同样须在 prompt 中显式携带。

## 🔍 文献实测检索铁律(2026-09-03 用户硬性要求 · 2026-09-04 补充关键词自动触发 · 生成"参考文献"部分时强制执行)

> **凡涉及"参考文献 / 文献综述引用"的生成，必须用浏览器技能(BrowserSkill)打开中国知网(https://kns.cnki.net)实测检索，逐条核实文献真实存在，禁止凭记忆默写文献。**

### ⚡ 关键词自动触发(2026-09-04 用户要求 · 命中即自动启用,不询问)

1. **触发关键词**(用户消息或任务描述中出现任一即触发):
   - 论文类: 论文、文献、参考文献、引用、综述、研究现状、文献检索、查文献、知网、期刊
   - 项目类: 项目文献、课题检索、查资料、文献支撑、立项依据(涉文献部分)、核心期刊
2. **触发动作(三步,自动执行)**:
   - ① **自动加载 BrowserSkill**(browser-skill),不再等用户点名;
   - ② **主动提示用户**: "接下来将用浏览器打开中国知网(kns.cnki.net)实测检索文献,请确保浏览器已打开且知网处于可访问/已登录状态"——知网检索需要登录态,BrowserSkill 借用用户真实浏览器环境,用户配合打开知网后检索成功率最高;
   - ③ 直接进入下方实测检索流程(bsk session start → navigate 知网 → 检索抓取),全程不必再次询问是否用浏览器。
3. **未命中关键词但任务确需文献** → 提示一句"是否需要联网实测检索文献?"再执行;命中关键词则免问直接做。

1. **触发场景**：任何产出含"[参考文献]"清单、或正文含"[n]"文献引用锚点（申报书/结题/论文/活页论证等）的文档。
2. **执行流程(不可省略)**：
   - 用浏览器技能(browser-skill 的 bsk CLI)开会话 → 导航知网检索页 `https://kns.cnki.net/kns8s/defaultresult/index?kw=<URL编码关键词>&korder=SU`
   - 检索关键词 = 课题核心方向拆成多组（如"校园足球体教融合""青少年足球训练监控""运动损伤预防"…），每组抓取结果列表前 10-20 行
   - **期刊行为主**: 用 evaluate 抓 `.result-table-list tr` 的 题名|作者|刊名|发表时间;默认收"期刊"行(排除报纸),社团课题/论文类文档可酌情收会议论文集([A]/[C])与学位论文([D]),但每条须单独精确检索核实,与下方「引用规范·必须正式文献」口径一致
   - 对拟引用的每条，**再单独用题名精确检索一次**核实存在性与年份
   - 只记录知网页面**实际显示**的 题名/作者/刊名/年份；**期号/卷号不确定就省略，绝不推测补写**
3. **引用规范**：
   - **条数默认与确认(2026-09-09 铁律)**: 参考文献默认 **10 条左右**;动笔前主动询问用户需要多少条,用户指定则按用户数执行;条数宁少勿滥,不凑数;
   - **必须正式文献**: 只收正式出版物——期刊论文(标注刊名)、学术专著、政府/官方政策文件、学位论文(视文档要求, 格式含导师名)、会议论文集论文([A]/[C]格式),严禁网页文章、自媒体、百科、无法核实的材料;
   - 数量上限按文档要求(活页≤20),一般 3-5 篇核心文献详述、其余一句带过;
   - 优先核心期刊(体育科学/中国体育科技/学报等)，近三年优先（默认当前年份往前推 3 年,用户指定年份则按用户指定）;
   - **序号从上往下 1→N 正序，严禁倒序或乱序穿插**;
   - **编号 = 正文首次引用顺序(2026-09-11 用户硬性规则)**: 文献表编号必须与正文中首次出现的先后顺序完全一致(谁先被引用谁排 1),**中英混排、不按语种分组**(禁止"中文N条在前+英文N条在后"的语种分组排法); 正文引用后编号顺序一经确定不再调整,增删文献须整体重排;
   - 工具校验: `tools/check_doc.py` 已内置"编号是否按正文首次引用顺序"检查项,出稿必跑;
   - 用户指定"只要近三年"时，全部条目年份须在近三年内;
   - **BrowserSkill 提醒**: 涉及参考文献时,主动提醒用户"可使用 BrowserSkill(browser-skill)打开知网实测检索,确保文献真实";命中触发词则按三步触发动作直接执行,不必等点名。
4. **用户疑问处理**：用户说"知网搜不到"时 → 立即当场用浏览器逐条复验，把实际检索结果展示给用户，搜不到就删、不辩解。
5. **写稿顺序**：先实测检索确认真实文献 → 再写正文引用锚点 → 锚点编号必须与文献表一一对应（写作后用脚本校验：正文 [n] ⊆ 文献表编号）。

> 2026-09-03 活页实例：13 条全部经知网实测检索核实（体育科学/上海体院学报/天津体院学报/广州体院学报/中国体育科技等），期间曾发生第一版凭记忆写的推测年份/期号被否决 → 浏览器逐条复核修正。

### 第二步 · 确认项目名称流程(选题方法论 — 2026-08-31 整合「体育论文选题」通用化)

> **原则: 不随意起题。** 用户给出方向后, 按「多因素定范围 → 分层递进 → 构造问题 → 维度改造 → 诊断校验」生成候选题目; 每个题目必须能回答"研究谁、在哪、什么现象、用什么材料、回答什么问题"。

1. **信息收集(最多问 3 个决定性问题的提问策略)**: 用户给方向后, 先确认其真实积累——长期从事的领域/专项、可合法获得的对象/数据/材料、最近反复遇到的具体现象。已答项不重复追问。
2. **多因素选取题目范围(核心)**: 联网调查 + 四方面交叉, 先确定「题目范围」而非直接出题:
   - **政策**: 检索最新政策文件、专项选题指南、对应类型的评审偏好;
   - **社会需求**: 现实痛点、行业/基层实际需求;
   - **学科前沿**: 研究空白与热点、他人研究的局限;
   - **申报者资源**: 领域积累、可获取的数据/样本/平台。
   - 产出 2-3 个候选「题目范围」, 每个说明其政策依据、需求依据与可行性依据。
3. **分层递进, 不跳步**: 研究领域 → 研究方向 → 现实问题 → 研究问题 → 题目。禁止把宽泛领域直接包装成题目。
4. **从"不对劲"进入问题**: 每个范围找一个可观察冲突(常识预期 vs 实际表现、政策落地后的意外偏差、教学/训练有效但真实场景失效等)。
5. **构造研究问题(链条式)**: 具体场景 → 具体对象 → 具体现象 → 可比较差异/冲突 → 可能解释 → 可验证疑问句。优先写成一句问句:"在__场景中, __对象的__现象为什么/在什么条件下__?"
6. **给出 5 个候选题目**(有实质差异, 非仅换地区/年份): 用六类维度(对象/情境/变量现象/理论/方法/时间制度)改造, 每个候选至少变两个维度。
7. **题目诊断与因果词强度校验(自检)**: 拆解每个候选的 对象/场景/变量/理论/方法/结论强度; 找「一个最大问题」(不并列堆缺点); 排除常见陷阱——堆热点词(赋能/机制/高质量发展)、强因果词滥用、范围跨全国多学段多主体、仅换地区年份、只有"价值/意义/路径"无可证伪问题; 因果词按设计强度匹配(横断面用"关联/关系", 实验/准实验才用"影响/效果")。
8. **用户选定 → 选题诊断三问(可行性复核)**: 真问题(2 个具体场景)/小切口(再缩小一个粒度)/可操作(数据样本可得) + 拟题公式(研究对象+研究问题+研究方法/视角)。
9. 题目规范: 合理性、体现价值意义优先, 字数 8~20 字左右(非绝对, 允许适当调整)。

> **指定选题类专项的适配**(2026-08-30 实测大体操专项发现): 若申报通知规定"按指定课题题目申报, 不得自行拟定"(常见于部委专项/省市级指南课题), 本第二步改为「联网获取指定选题清单 → 用户选择 → 选题诊断三问做**可行性评估**(不改题不自拟)」, 上面第 2-7 步的自拟建议流程跳过。

> **体育方向**: 体育方向选题可额外加载「体育论文选题」skill 做深度诊断; 本流程已将其方法论**通用化**, 适用于所有项目类型, 不限于体育。

```
🔶 需确认(3项): 项目关键词、经费预算、预期成果
❓ 必须索取(15项): 推荐学院、项目名称、负责人姓名、学号...
⁉️ 可选(4项): 指导教师工号、成员Email...
```

> 原则:宁可多问,不可编造。任何无法从项目主题推导的个人信息,一律归入❓或⁉️。

### 步骤 2.6: 项目思考环节(核心 — 生成前必做,不可跳过)

> **定位**: 在「第一步确定题目」之后、「框架设计(步骤 6B)」之前,对题目做一次**载体类型 + 科研范式**的双重判定,据此决定正文**必须加入哪些方法论要素**。完整范式定义见 `reference-db/research-paradigms.md`,本步骤按以下五小步执行。

> **核心区分**: **载体类型决定格式,科研范式决定内容要素**。两者正交,必须分别判定。

**① 判定载体类型** — 明确题目属于(与前置流程第一步口径一致): 大创 / 教师科研 / 论文 / 省市级课题 / 国自然 / 其他。
- **其他** → 格式口径按「通用模板 + 底板确认流程」执行(执行魔板为准);科研范式仍按 ② 判定,必加要素照常挂载
- **以用户提供的参考文件为主**(参考文件是格式口径的一手依据)
- 参考文件不够详细 → 回退到 `schools/{学校}/{项目类型}/` 的母版与 format.md
- 锁定: 格式口径、章节结构、字数、评审重点

**② 判定科研范式** — 读 `reference-db/research-paradigms.md`,把题目归入 5 类之一:
- ① 调查/实证类(探究影响路径、现状、规律)
- ② 实验/技术类(材料/医学/工程/算法、数据密集)
- ③ 设计/工程类(造系统/产品/方案)
- ④ 政策/文献类(政策分析/文本/历史)
- ⑤ 纯理论类(数学/理论推导)

**③ 挂必加要素** — 按范式从 `research-paradigms.md` 第二节点,确定正文**必须出现**的方法论要素:
- 调查类 → 样本设计、问卷/访谈方法、变量指标、数据分析、信效度
- 实验类 → 实验设计、材料与方法、性能指标、性能目标预估(有文献才做)、对照验证
- 设计类 → 需求分析、系统架构、技术路线、方案论证、原型验证
- 政策类 → 政策/文献库、文本分析方法、演进脉络、理论与实践对接
- 理论类 → 理论框架、假设命题、推导逻辑、边界条件

**④ 能力匹配评估**(借鉴 Supervisor-Skills idea-evaluator):
- 该题目在当前申报者身份(本科生/研究生/教师)下是否可执行?
- 可执行 → 正常展开; 部分超出 → 保留框架 + 标注局限; 明显超出 → 明确"本项目不作…留待后续",不硬凑

**⑤ 产出研究设计契约**(借鉴 nature-proposal-writer 的 proposal-first):
- 先锁定: 证据来源(真实政策/文献/数据) → 核心论证逻辑 → 章节契约(每章要论证什么)
- **契约形成后,才进入步骤 6B 的标题构思与内容深化**,避免"先写内容再回头补方法"的倒置

> 输出: 向用户简要呈现「载体类型 + 科研范式 + 必加要素 + 能力匹配结论」,确认后进入后续步骤。

### 步骤 6: 博士水准主题深度分析(强制 — 生成内容前必须完成)

> **本步骤是内容质量的根基,不可跳过。** 在对项目主题进行博士级学术分析后,再规划内容结构。

**6A. 主题分析维度**(每个维度150-300字深度分析):

| 维度 | 分析内容 | 产出 |
|------|---------|------|
| 🎯 **核心价值** | 该主题在学术/政策/实践三个层面的价值分别是什么? 解决了什么空白? | 3句话,每句对应一个价值维度 |
| 💡 **深层意义** | 该研究对学科发展、社会需求、政策落地的深层意义? 超越表面描述的洞察? | 2-3个关键洞察 |
| 🔗 **研究目的** | 要回答的核心问题是什么? 预期的知识贡献或实践产出是什么? | 核心问题陈述 + 预期产出 |
| ⛰️ **实现难度** | 数据获取难度/方法论要求/理论复杂度? 本科生在指导下能否完成? | 难度评估 + 可行性判断 |
| 🗝️ **可解决关键点** | 在有限条件下,哪些子问题可以切实解决? 哪些需要留作开放问题? | 可解/可探索/留待未来的分类 |
| 🛤️ **解决方案路径** | 从主题到结论的方法论路径? 技术路线? 分几步走? | 3-5步路径描述 |

**6B. 标题层级构思(先标题后内容 — 强制,不可跳过)**

> 核心顺序:**先构思全部标题,再深化写内容**。标题定了,内容才有骨架。

**6B-1. 构思顺序(自上而下逐级锁定)**:

1. **一级标题**: 严格按母版(一、申请理由 / 二、项目方案 / 三、学校提供条件 / 四、预期成果 / 五、经费预算),不改
2. **二级标题((一)(二)...)**: 根据题目和一级标题,构思逻辑递进的子节。**先全部列出,再逐个检查是否紧扣一级标题**
3. **三级标题(1. 2. 3.)**: 在每个二级标题下,进一步分解论述点。**同样先列全,再检查紧扣二级标题**
4. 标题全部构思完成后,输出完整标题大纲给用户预览,再进行内容深化

**6B-2. 标题紧扣原则(环环相扣)**:

- 每个**二级标题**都必须能回答:"它是这个一级标题的哪个侧面?" 答不上来就说明偏题,要改
- 每个**三级标题**都必须能回答:"它支撑二级标题的哪个要点?" 答不上来就删
- 禁止出现与上级标题无关的"自由发挥"标题

**6B-3. 标题去AI化(避免模板化 — 调用 humanizer 方法论)**:

AI 常见的标题毛病是"机械编号 + 泛化命名",如:
- ❌ "1. 创新点一""2. 创新点二""3. 创新点三" — 没信息量,纯编号
- ❌ "研究内容一/二/三" — 同样泛化
- ❌ "1. 具有重要意义的研究" — 空话

正确的标题应该**根据实际内容命名,有具体内涵**,如:
- ✅ "1. 双期对比视角下的机制整合"
- ✅ "2. 四维分析框架的构建与应用"
- ✅ "3. 宏观政策与基层传导的贯通"

**6B-4. 标题风格(官方正式,不白话)**:

- 用学术化、书面化的表达,避免口语大白话("聊聊""看看"这类绝不能用)
- 但同样避免 AI 味的大词空话("赋能""抓手""闭环""范式"等滥用词慎用)
- 平衡点:**正式、准确、有信息量**,既不是聊天腔,也不是 AI 腔
- 命名规范(参考 format.md): 10-20 字,精炼,一看标题就知道这节讲什么

**6B-5. 字数随标题优化**:

- 标题确定后,按标题的重要性和承载量分配字数
- 核心标题(如"研究目标及主要内容")配更多字数,次要标题(如"成员分工")配少字数
- 每个三级标题下的内容,以"能讲透这一小点"为准,不强行凑数也不一刀切

**6B-6. 段落逻辑顺序(2026-08-16 经验固化 — 强制,不可违反)**:

> 教训: 之前多轮扩充用"标题后追加"方式,把新内容堆在标题正下方,导致总起句被挤到末尾、结论句跑到开头,段落顺序严重错乱。

- 每个标题下的段落,必须按"总起 → 展开 → 结论"的逻辑顺序**一次性写好**
- **禁止用"标题后追加"方式扩充内容**——内容需要补充时,应**重写整个章节**,而不是在标题后堆新段落
- 生成后自检: 每个三级标题下,第一段应是总起(如"这是研究的基础环节"),末段应是收束(如"梳理成果将沉淀为..."),中间是分述
- 若发现段落顺序错乱,立即重写该章节,不要靠微调修补

**6C. 字数规划**(参考原始文件分析标准):

| 级别 | 每项字数 | 说明 |
|------|---------|------|
| 一级章节 | 800-5000字 | "二、项目方案"承载核心内容,字数最高 |
| 二级子节 | 400-800字/节 | 如创新点、研究内容子方向 |
| 三级论述点 | 200-500字/点 | 每个论述点含"论点+论据+延伸" |
| 正文段落 | 150-300字/段 | 3-5句,长短交替 |

### 步骤 7: 深度研究

对项目主题进行:
- **政策解析**: 检索相关政策文件(可用 WebSearch),引用具体政策名称与要点
- **研究现状**: 梳理国内外研究现状,找到研究空白
- **本校/本地对接**: 体现与学校特色/区域需求的对接

**7A. 文献筛选六维评分(撰写"研究现状/文献综述"时 — 2026-08-16 借鉴 nature-literature-pipeline)**

> 撰写研究现状、梳理已有研究时,用六维评分筛选**值得引用**的文献,避免堆砌无关/低质文献。

| 维度 | 权重 | 评分标准(申报书场景) |
|------|------|---------------------|
| 主题匹配 | 35 | 与项目主题直接相关度(越直接分越高) |
| 权威性 | 20 | 来源是否权威(核心期刊/官方政策/知名学者) |
| 时效性 | 15 | 是否近年发表(前沿领域如 AIGC 优先近 1-2 年) |
| 可引用性 | 10 | 是否有明确出处、可查证(不引用查无实据的) |
| 支撑价值 | 10 | 能否支撑"研究意义/研究空白"的论证 |
| 本土相关性 | 10 | 是否与中国/本地实际相关 |

**筛选规则**:
- 候选文献逐一六维打分,总分 ≥ 60 分才引用;高分区(≥80)优先详述,低分区(60-70)一句带过
- 引用时标注来源(作者/年份/期刊或机构),**严禁编造文献**(查无实据的不用)
- 研究现状部分引用 3-5 篇核心文献即可,不堆数量,重质量

**7B. 综述写法与研究现状框架(2026-08-30 吸收 kunlun-edu-research-agent / research-academic-helper)**

> 触发: 撰写"研究现状/文献综述"部分时自动使用。

- **先选综述类型**: 时序型(演变历程) / 主题型(多维度) / 方法论型(方法比较) / 理论型(框架与争议), 按选题选一种
- **每个脉络按「共识 → 分歧 → 空白」三步写**: 先说领域共识, 再说哪些点有分歧(及原因), 最后落在研究空白——只罗列文献不加评论是最常见错误
- **文献卡片法**: 精读每篇记 5 项(研究问题/方法/主要发现/局限/与本研究的关联), 按"关联"归类建脉络; **他人的"局限"就是本课题的潜在创新点**
- **需要主动检索时先写检索式**: 核心概念同义词(中英文) → 布尔组合式 → 纳入/排除标准 → 从高质量文献参考文献滚雪球补漏

### 步骤 8: 生成内容(按信息分类处理)

按学校 format.md 的章节结构逐章生成,**严格遵守信息分类矩阵**:

**8A. 处理 ❓ 未知·必须索取 字段**:
- 生成到该字段时**暂停**,按 format.md 中的询问格式向用户索取
- 得到用户回复后填入,不得自行编造
- 若用户一次提供多个字段,批量填入
- 若用户表示"稍后提供",填入占位符 `[待填写: {字段名}]`

**8B. 处理 ⁉️ 未知·可选 字段**:
- 询问一次,用户能提供则填入,不能提供则标注 `[待补充]`

**8C. 处理 🔶 已知·需确认 字段**:
- 基于项目主题生成建议值
- 提示用户:"建议{字段}: {建议值},是否采用或需调整?"
- 用户确认后填入,调整则按用户值

**8D. 处理 ✅ 已知·自动生成 字段**:
- 基于: 项目主题 + 政策环境 + 学校特色 + 思考流程输出
- 直接生成,无需询问
- 符合**学生身份水准**(在读研究生/博士生):学术规范但不拔高,体现探索性
- 套用**确认的字体字号**
- 引用规范完整,标注来源
- 预留配图位置(图1/图2...)并附图注说明
- **嵌入学术写作**(见下方"8E")+ **去AI味**(见下方"8F"): 生成时同步应用
- **⚠️ 字数深度要求**(基于原始文件对比):
  - 总字数: 8,000-20,000字,目标12,000字
  - 各章节不低于format.md中的最低字数,优先逼近目标字数
  - 创新点/研究内容/关键问题严禁"一句话带过",必须展开深层分析
  - 每段至少3-5句,核心观点需有解释/例证/延伸三个层次

**8E. 学术写作(默认启用 — nature-polishing 适配版)**

> 生成 ✅ 内容时**同步**应用学术写作规范,提升学术严谨性。方法论借鉴 nature-skills 的 nature-polishing(段落逻辑、术语一致性、声称漂移)。
> **与 8F 去AI味的分工**: 8E 学术写作管"严谨性"(结构/逻辑/术语/声称),8F 去AI味管"自然性"(去 AI 腔/注入人味),两者不重叠、先后配合——**先 8E 后 8F**。

**学术写作职责(管"严谨性")**:

1. **段落逻辑顺序**: 根据问题提出、比较、论证及研究安排确定顺序;**不固定"总起→展开→结论"**;补充内容时检查上下文承接,只修改受影响部分,不要求整章重写
2. **内容去重**: 删除重复段落(如同一结论多段重复表述、同一"此外..."多段并列)
3. **术语一致性**: 同一概念全文统一;相关但范围不同的概念分别定义——如 AIGC 与人工智能范围不同,不能为减少重复相互替换
4. **声称漂移修正**: 核查判断的依据与适用范围;证据不足时删除或限定判断,**不能只把"重大突破"换成"探索"便视为论证成立**
5. **数值精度**: 数据前后一致、有出处可查

**关键约束(避免与 8F 冲突)**:
- 8E 只改"严谨性",不改语言风格——不做口语化;8F 同样**不得添加情绪或虚构经历**
- 8E 修正术语时,不得改动政策名称、数据、学术引用等事实

**8F. 去AI化描述(嵌入生成 — 默认启用,不额外全量重写)**

> 生成 ✅ 内容时**同步**用真人笔法书写,避免生成后全量重写。完整方法论见 `humanizer` skill(去AI味 v4.1)。
> **重要**: humanizer 通用版面向网文/公众号,本步骤是**科研申报书场景的适配版**——保留学术文书的严谨性,只去除 AI 味的空洞与套路。
> **执行铁律(2026-09-01)**: 启用 humanizer 时,必须完整走 `humanizer` 的 Phase 1→4 全流程 + L1~L4 四层自检 + 改写后交互,**不得只做嵌入式写作 + 轻量终检就收尾**。嵌入式写作只是"写的时候避免 AI 味",不能替代生成后的完整检测与定向修正流程。

**场景适配原则(先分清"该留"和"该去")**:

| | 内容 |
|---|---|
| ✅ **保留**(学术文书需要) | 冒号/破折号、清晰的分点结构(申报书要求分点)、"首先/其次"等逻辑递进(学术论述正常)、"如图X所示"等规范表述 |
| ❌ **去除**(AI 味特征) | 假靶子"不是A而是B"、空话大词、虚假宣告、AI 幻觉假数据、万能句式、莫名比喻、机械三段式堆砌 |
| 🚫 **禁用**(网文口语,绝不用于申报书) | "这玩意""不是哥们""说白了""你品一下""稳稳接住你"等口语化表达、玩梗、自问自答老师腔 |

**第一步 · 检测 AI 痕迹(生成时同步自检,重点 6 类)**

1. **假靶子"不是A而是B"**: "本项目的意义不是停留在X,而是Y"——前半句否定的观点没人提过,直接删前半句只写 Y
2. **空话大词**: "意义重大""影响深远""具有重要的理论意义和实践价值""发挥着重要作用"——一律换成具体内容(重大在哪?对谁重要?)
3. **虚假宣告**: 只宣布重要性不给证据:"其重要性不言而喻""这引发广泛关注"——删,换成具体说明
4. **万能句式**: "值得注意的是""综上所述""随着...的发展""在...的背景下""众所周知"——删掉,直接说内容
5. **AI 幻觉/假数据**: "某研究显示""专家普遍认为"查无实据——只写可查证的政策名称和数据
6. **机械三段式**: "首先...其次...最后..."+"一方面...另一方面..."连续堆砌——打散,保留真实逻辑递进
7. **引号滥用**: 中文引号("")过度使用——一段内多处、全文几十对,是明显的 AI 味特征

**引号使用规则(2026-08-15 用户要求,铁律)**:

- 中文正文用**中文弯引号**(""),**不用英文直引号**(")
- **频率控制**: 一篇约 1 万字文章,引号总量控制在 **30 对以内**,一段(约 150 字)不超过 1-2 对
- **只加必要引号**:
  - ✅ 特定称谓/专有名词("戏曲活化石""傩小桂"这类)
  - ✅ 特殊含义/反讽("伪非遗""翻译"这类)
  - ✅ 引用特定表述("内容为本、AI为用"这类)
  - ❌ 普通关键词不加("机制""路径""赋能"这类一律不加)
- **优先用自然表述替代引号**: 能不加就不加,用顿号、冒号、破折号或直接叙述替代
- **生成后自检**: 全文引号对数超过 30 对即需删减

**第二步 · 就地重写(保留原意,改掉 AI 味)**

| AI 写法 | 申报书真人写法 |
|---------|--------------|
| 本研究具有重要的理论意义和实践价值 | 本研究可为 XX 学校体育教学改革提供可操作的方案 |
| 值得注意的是,体育功能发生了转变 | 体育功能从民生事业转向了经济引擎(直接说) |
| 其重要性不言而喻 | (删掉,直接展开论述) |
| 首先A,其次B,最后C(机械排比) | A是基础;B是关键;落到实践,则是C(递进而非罗列) |
| 专家普遍认为... | 依据《体育强国建设"十五五"规划》,... |

**第三步 · 注入"人"的痕迹(学术文书内适度)**

- **真实思考过程**: "在研究过程中我们发现……"优于直接下结论
- **坦诚局限**: "这个问题目前还没完全想清楚"比装作什么都懂更可信
- **具体数字与场景**: "人均场地从3.11增至4m²"优于"显著提升"
- **长短句交错**: 短句与长句交替,打破 AI 均匀节奏
- **学生视角**: "在指导教师帮助下""通过查阅资料我们发现"符合学生身份

**第四步 · 关键约束**

- 指导教师信息、政策名称、数据、学术引用**不得因去AI化改动**——只改表述,不改事实
- 学术术语、规范表述(如图注"图N...")保持原样
- 不追求"口语化",只追求"自然"——申报书要的是"像认真的人在写",不是"像在聊天"
- 总原则:**去掉 AI 的空洞和套路,保留学术的严谨和具体**

**Token 控制**: 去AI化在生成时同步完成(写的时候就用真人笔法),不产生额外全量重写成本。仅对漏网的明显 AI 感段落就地微调。

> 铁律: ❶ 不得编造任何个人信息(姓名/学号/电话/工号等) ❷ 不得遗漏任何❓字段(必须问) ❸ 不得跳过任何✅字段(必须生成) ❹ 生成完毕后输出信息完整性报告
>
> **关于"指导教师信息"的特别强调**:
> 指导教师的"研究方向/主要成果/学术任职"等字段,**绝对不可自动生成**,即使知道姓名也不能"反推"。因为:
> - 反推可能不准确(同名教师、不同研究方向)
> - 编造学术成果是严重的学术不端
> - 这些信息只有用户(学生)最清楚
>
> 必须向用户询问的具体字段:
> - 研究方向 / Research Direction
> - 主要成果(论文/项目/奖项等)
> - 学术任职(如期刊编委、学会会员)
> - 年龄(如学校要求)
> - 与本项目的关联说明
>
> 即使学校格式中没有显式列出这些字段,生成时也应主动询问并补充到指导教师表中。

### 步骤 8.5: 图片插入(内容生成后 — 穿插正文)

> 正文生成完成后,按参考文件的方式在正文中**穿插插入图片**,紧跟相关论述,不破坏整体格式。

**图片数量(硬性要求)**:
- 一篇文章内图片**不得少于 5 张**,一般在 **10 张左右**,根据项目需求确定
- 图片不足 5 张视为不合格,需补充

**插入方式(严格按参考文件)**:

1. **穿插位置**: 图片紧跟相关论述段落之后,不堆在文末。典型位置:
   - 项目简介之后 → 政策文件/背景相关图
   - 研究背景/研究现状之后 → 关系图/框架图
   - 研究内容之后 → 模式图/示意图
   - 技术路线之后 → 技术路线图

2. **插入格式**:
   - 图片**独占一个段落**
   - 图片下方紧跟**图注段落**: `图N + 说明`,居中
   - 图片宽度约 **14.5cm**(接近满版),高度按比例自适应
   - 图注字体: **随学校正文字体**(池州学院=仿宋 / 阜阳师范大学=宋体),小四或小五,居中

3. **生成方式(生图渠道) — 默认科研绘图 + AI绘图,缺失时提醒**:
   - **默认启用科研绘图(nature-figure 方法论)**: 用于关系图/框架图/流程图/数据图表等**结构化图**,面向投稿级科研图的 Python/R 工作流(文字精确、可复用)。上游同步(2026-09-17)补三项门禁: **多面板证据架构**(一张图回答一个结果级科学问题,各面板分别承担主证据/对照/正交验证/扰动/机制/边界等不同推理角色,禁同一结果换指标重画) + **渲染时面板对齐门**(多面板图导出前实测同行/同列轴框、宽高、panel 标签锚点与重复间距,1.5pt 容差,可靠错位阻断导出,自由定位主面板/inset/colorbar 须带理由豁免) + **成图碰撞审计**(每次重绘后检测文字-文字/文字-线条/页面裁切/色块边缘重合,可靠碰撞必修,可疑 overlay 逐项复核,生成 collision JSON 留档)
   - **默认启用 AI绘图 skill(即 nano-banana-pro,基于 Gemini 3 Pro Image)**: 用于概念示意图/产品设计图等**视觉图**
   - AI绘图 调用方式: `uv run {baseDir}/scripts/generate_image.py --prompt "..." --filename "..." --resolution 1K|2K|4K`
   - AI绘图 工作流: 先 1K 出草稿 → 微调 prompt 迭代 → 定稿后 4K 输出
   - **⚠️ 缺失/调整时提醒用户**:
     - 若未检测到 AI绘图 skill 或 API key → **主动提醒用户**:"当前环境未检测到 AI绘图 skill 或 API key,请提供生图渠道(API key / 本地生图工具 / 其他接入方式)",等用户提供后再继续
     - 若 AI绘图 skill 被用户调整或更换了生图渠道 → 记录新的渠道,后续按新渠道执行
   - **除非用户手动调整,否则一直默认使用上述生图方式**

4. **图片类型清单**(根据项目需求选用):
   - 政策概念图(政策文件要点/政策脉络)
   - 项目计划图(项目规划/阶段安排)
   - 流程图(研究流程/业务流程)
   - 概念图(概念关系/知识结构)
   - 市场数据展示图(市场规模/趋势图表)
   - 重要数据展示图(核心数据可视化)
   - 产品设计图(产品/系统/模型设计)
   - 关系图/框架图/模式图/技术路线图

5. **图片内容分析(生成前必做)**:

> 每张图片生成前,先判断它的"文字密度"定位,决定生成时文字配多还是配少:

| 图类型 | 文字多少 | 定位 |
|--------|---------|------|
| 政策概念图 / 技术路线图 / 流程图 | 文字较多 | **文字配图的介绍图**(展示要点/脉络/步骤) |
| 概念图 / 框架图 / 关系图 | 文字适中 | 文字配图的介绍图(展示结构关系) |
| 数据展示图(市场/重要数据) | 文字+数据 | 数据图表(数据为主,文字标注) |
| 产品设计图 / 展示图 | 文字少 | **产品的展示图**(展示外观/形态,少文字) |

- 文字配图的介绍图 → 生成时文字多、清晰可读,突出内容要点
- 产品的展示图 → 生成时文字少,突出产品/系统外观与形态

6. **图片类型分工(生成方式)**:
   - 关系图/框架图/模式图/技术路线图/流程图(需文字精确、结构化) → **科研绘图(nature-figure 方法论)**
   - 数据图表(柱状/热力/森林/KM/ROC等, 有结构化数据) → **academic-figures**(默认) 或 **EditaPlot**(本机有 Origin 且需可编辑 OPJU 的材料/光谱/医学数据, 见按需功能触发表)
   - 概念示意图/产品设计图/装饰图(文字要求低) → **AI绘图(nano-banana-pro)** 文生图

7. **穿插密度(第一原则:根据内容来)**:
   - **第一原则**: 根据内容需要配图,哪里内容需要图就插哪里,不为了凑数量硬插
   - **不要过于密集**: 避免连续多张图挤在一起,让图分散在整篇正文中
   - **允许接近**: 允许两张左右图片比较接近(相邻),但最多不超过连续3张
   - 穿插位置以"内容相关性"为准,不是均匀分布

8. **不得破坏格式**: 插入图片和图注时,严格沿用正文的段落格式(首行缩进、行距),不得改动母版边框、表格结构。

调用 `research-quality-check` 技能,核对:

- 必须生成点 ✓(内容硬约束)

### 步骤 9.5: 项目逻辑审核(轻量 — 不可跳过)

> 在格式校验通过后,对项目整体进行一次**轻量快速**的逻辑审核。聚焦核心问题,不逐字审查。

**审核清单**(每个维度一句话结论即可):

| 维度 | 检查内容 | 标准 |
|------|---------|------|
| ⏱️ 时间逻辑 | 实施起止时间/申报日期/年级等信息是否一致? 进度安排各节点是否与总周期匹配? | 不能出现"2026年5月启动→2026年4月完成"这类倒挂 |
| 🔗 内容逻辑 | 各部分之间是否自洽? 研究目标/内容/方法/预期成果是否互相矛盾? | 不能出现"研究方法用问卷"但"预期成果有实验数据" |
| 🎯 是否跑题 | 所有章节是否围绕项目核心主题? 有无无关内容或过度发挥? | 每章开头一句话能回答"这和本项目有什么关系" |
| 📝 核心描述一致 | 项目简介中的概述与实际生成内容是否一致? 关键术语定义是否前后统一? | 简介说的A,正文写的也是A,不是A+B+C |

**审核方式**:
- 不重新读取全文,基于已生成的内容做**抽查式逻辑验证**
- 每项 1~2 句话评价: ✓ 通过 / ⚠️ 需修正(指出具体问题)
- 有 ⚠️ 则修正对应段落,不重写全文
- Token 预算: 此步骤控制在 500-800 token 以内

**输出格式**:
```
📋 项目逻辑审核报告
⏱️ 时间逻辑: ✓ / ⚠️ (一句话说明)
🔗 内容逻辑: ✓ / ⚠️ (一句话说明)
🎯 题目聚焦: ✓ / ⚠️ (一句话说明)
📝 核心一致: ✓ / ⚠️ (一句话说明)
```
全部 ✓ 则继续; 有 ⚠️ 则修正后继续。

### 步骤 10: 应用学校格式(母版分层处理)

> **母版分层的完整规则(两校结构差异/项目名称填写位置/分层细节/标题层级格式)已下沉到 `research-dachuang` skill「二 · 母版分层走法」,本文件不重复。** 生成时加载 `research-dachuang` 并按其中学校对应规则执行。

**执行要点速记**:
- **池州学院**: 4 表结构,项目名称填**表2 信息表行0列1**(封面不填),正文仿宋;表0/表1 完全不动
- **阜阳师范大学**: 封面表 + 24×10大表,项目名称填**第二页 B区(c4-c9)**,正文宋体;第一页/第二页保持母版不变,正文在母版基础上追加
- **教师科研线活页**不走本步骤母版分层,按 `research-teacher-project` skill「活页子流程」的底板合成方式执行(不解构、不替换底板骨架)
- **论文线**不套用学校母版,按 `research-writing` skill 的目标期刊/参考论文格式执行

- 封面与基本信息
