# 科研项目文档 — Plus 深度科研增强版

## 用途

在普通版(标准生成)基础上,为深度科研需求用户提供增强:审核返修循环 + 科研化描述 + 数据比对与性能支撑。所有类型通用(大创/教师科研/论文/省市级课题/国自然/其他-通用模板,校级/横向为预留类型)。

## 触发方式(两种)

1. **前置触发**: 项目建立时,用户明确说"启用 plus 版本""深度科研""深度研究"等 → 直接按 Plus 版生成
2. **后置提示**: 普通版生成完成后,做一个小提示:"已完成普通版,如需更深入的学术含量,可升级为 Plus 深度科研版,是否升级?" —— 用户确认后再升级

> 默认**不启用**,仅当用户明确要求时启动。用户未要求时保持普通版,不主动升级、不纠缠。

## 模块一 · 三轮审核-返稿-重修循环

借鉴 nature-reviewer(审稿) + nature-response(返修),构建"审核员 → 返稿 → 重修"循环,**反复三次**。

### ① 审核员模式(按科研类型区分身份)

| 科研类型 | 审核员身份 | 审核重点 |
|---------|-----------|---------|
| 大创 | 大创评审专家 | 创新性、可行性、学生能力匹配、成果适宜 |
| 教师科研 | 科研项目评审专家 | 学术价值、研究基础、方法科学性、经费合理 |
| 国自然 | 国家自然科学基金评审专家 | 科学问题属性、创新性、研究方案可行性 |
| 省部级 | 省级科研项目评审专家 | 区域需求对接、应用价值、团队实力 |
| 校级/横向 | 校级/企业评审 | 可操作性、落地价值 |
| 通用模板 | 通用审核编辑 | 内容完整、逻辑通顺、格式规范 |

> **触发时先确认科研类型**,据此切换审核员身份。不同科研类型采用不同的审核方式与审核员模式。

### ② 每轮审核流程

1. 以对应类型的**审核员视角**通读全文,评定项目
2. **标记问题(分级)**:
   - 🔴 重大问题: 内容缺失 / 逻辑矛盾 / 不符合官方文件要求
   - 🟡 一般问题: 表述不严谨 / 论据不足 / 术语不当
   - 🟢 建议: 可优化的细节
3. skill 根据标记的问题**返稿重修**

### ③ 三轮各有侧重

| 轮次 | 审核侧重 | 检查内容 |
|------|---------|---------|
| 第 1 轮 | 结构+内容完整性 | 符合官方文件要求吗?章节齐全吗?内容缺失吗? |
| 第 2 轮 | 逻辑+学术性 | 论证严谨吗?有逻辑漏洞吗?论据充分吗? |
| 第 3 轮 | 细节+表述 | 术语规范吗?科研化吗?无过度声称吗? |

每轮结束输出「审核报告 + 修改说明」,三轮后确保项目符合官方文件、内容和逻辑无问题。

### ④ 双视角审核机制(2026-08-30 新增,第 2/3 轮适用)

> 实测教训: 单一审稿角色有盲区——方法学审稿通过后,领域专家视角仍能发现"结果指标错配"等 6 个领域问题(如 Lysholm 不适用 KOA)。

- 第 2/3 轮审核时,同一轮内切换**两个视角**依次审:
  - **视角 1 · 方法学审稿人**(通用): 统计报告规范、样本量依据、偏倚控制(盲法/随机)、报告完整性
  - **视角 2 · 领域专家**(按选题领域切换身份): 临床/康复选题 → 临床专家(结果指标是否为该病金标准、安全性、依从性、诊断与基线); 工程/技术选题 → 领域工程专家; 政策/文科选题 → 领域研究专家
- 每个视角独立输出问题清单(🔴🟡🟢),合并去重后进入返稿重修
- 领域视角发现的问题多为**领域知识型缺陷**,修正时按 research-writing 的「A/B/C 三级修正法」C 类处理: 按领域金标准替换或补充,保留被替换项并降级说明

## 模块二 · 科研化描述

### ① 描述逻辑(面向重点科研用户)

重点科研需求用户需要的描述逻辑:
- **学术术语化**: 用领域规范术语,不用大白话(如"研究方案"而非"怎么做")
- **论证严谨**: 论点 → 论据 → 逻辑推演,不空喊口号
- **客观陈述**: 第三人称客观,避免"我觉得""我们认为"
- **规范引用**: 标注来源,可查证
- **严谨限定语**: 用"研究表明""初步探索""有待进一步验证"等严谨表述,不用绝对化断言

### ② 借鉴学术写作(nature-polishing)

- 段落逻辑顺序(总起→展开→结论)
- 术语一致性
- 声称漂移修正(不过度声称)
- 数值精度

### ③ 与去AI味(humanizer)的分工

| 能力 | 管什么 | 说明 |
|------|--------|------|
| 去AI味(humanizer) | 像不像人写 | 去空洞、去套路、注入人味 |
| 科研化(本模块) | 像不像科研人员写 | 学术化、术语化、严谨化 |

Plus 版 = 去AI味 + 科研化,两者叠加、各管一个维度、不冲突。

## 模块三 · 数据比对与性能支撑(理工科场景)

面向理工科、材料、医学、工程等**数据密集型**选题,在合适位置补充真实可查证的数据,增强论证的专业性与说服力。

### ① 触发条件(两种情况)

1. **自动采集**: Plus 版生成/审核时,若选题属数据密集型方向,且联网调研(WebSearch)已获取**真实可查证**的数据,则主动在合适位置加入数据比对与性能提升数据。
2. **用户提供**: 用户主动提供数据表、文献数据、实验数据或内容 → **优化后写入**(不照抄,见下方"数据铁律")。

> 数据来源优先级: 用户提供的数据(最真实) > 联网调研到的权威数据(期刊文献/官方报告/标准) > 不臆测、不编造。

### ② 数据位置(合适的地方)

| 位置 | 补什么数据 | 作用 |
|------|-----------|------|
| 研究背景/研究现状 | 材料性能参数、已有研究的性能提升数据 | 证明选题有据、领域了解深 |
| 关键问题 | 预期性能目标量级(用"拟/预期/争取达到"限定语) | 让目标可检验 |
| 技术路线 | 工艺参数参照(固化温度/压力/配比区间等) | 体现可操作性 |
| 可行性/基础条件 | 已有成果或设备的数据支撑 | 佐证可行性 |

### ③ 数据铁律(硬性)

- **只写真实可查证的数据,严禁编造**——这是不可逾越的底线,宁可少写也不造假
- 数据尽量**标注来源**(文献作者/年份/期刊,或官方/权威来源),至少保证可追溯
- **点到为止**: 申报书阶段补 2-4 处关键数据即可,不堆砌、不做大张数据比对表(那是结题报告/论文的事)
- **用户提供的数据要"优化"而非"照抄"**: 统一单位与精度、科研化表述、嵌入上下文逻辑、与论点结合(数据服务论点,不孤立罗列)

### ③-2 性能目标预估(用户未提供数据时 — 2026-08-18 新增)

> 数据密集型(实验/技术类)题目在**用户未提供任何数据**时,是否补数据,按下述规则,完整定义见 `reference-db/research-paradigms.md` 第四节:

1. **只做"有依据的目标预估",不做"虚拟实验数据"** —— 绝对不编造实测数据(如"本材料拉伸强度达 XX MPa"这种伪造的实验结果)
2. **有真实文献参数可外推** → 用限定语"拟达到 / 预期 / 争取达到" + 标注文献来源 + 说明假设条件
3. **无文献支撑、无法合理估算** → **明确不加**,不硬凑数据
4. 预估数据的位置: 研究现状(引用文献真实参数)、关键问题(预期目标量级)、技术路线(工艺参数参照)、可行性(已有成果支撑)
5. 与「科研范式②实验/技术类」的必加要素联动: 若判定为实验类,优先补"性能指标+对照基准",再考虑是否做目标预估

### ④ 文理科有别

- 理工科/材料/医学/工程 → 主动补充真实数据
- 纯文科(文学/历史/哲学) → 不强制,仅在有确凿数据时补充,不硬凑

| 维度 | 普通版 | Plus 深度科研版 |

## 模块四 · 水平定级与升级路线(2026-09-11 新增 · 对标国自然/省部级)

> **触发**: 用户问"这项目能到什么水平""能不能冲国自然/重点""按 XX 尺度看够不够格"时自动启用; 也可在 Plus 版审核后主动给出定级。

**① 定级五维(逐维打分 1-5,并给一句依据)**
| 维度 | 看什么 | 达标特征 |
|------|--------|---------|
| 科学问题 | 是"为什么/规律是什么"(科学问题),还是"怎么做"(技术/实践问题) | 重点: 机制/规律型 + 可检验假设 |
| 创新性 | 理论/方法原创 vs 组合与应用 | 重点: 有理论原创或方法学突破 |
| 研究体量 | 中心数、样本量、周期、经费量级 | 重点: 多中心 + 4-5 年 + 200-300 万量级 |
| 研究深度 | 有无机制层、中介/调节变量、剂量—效应 | 重点: 三条机制链 + 因果推断设计 |
| 研究基础 | 机制类前期成果、平台、团队构成 | 重点: 机制研究积累 + 跨学科团队 |

定级口径: 综合 ≥4 分可对标重点; 3-4 分对标面上; 2.5-3 分面上边缘或青年; <2.5 分建议投省市/校级/社团课题。

**② 逻辑贯通性两查(关键)**
- **应用逻辑链**: 问题 → 目标 → 内容 → 方法 → 指标 → 成果,查断点、孤儿项、越级承诺;
- **科学逻辑链**: 假设(H1/H2) → 变量(自变量/中介/调节/因变量) → 机制路径 → 证伪条件; 常见缺陷: 无假设链 / 指标与机制脱节 / 提出的缺口未落设计(如提"持续性"却无随访时点与保持率指标)。

**③ 升级路线模板(五步,按需给)**
1. **科学问题重构**: "如何做 X" → "X 的机制与剂量—效应规律",并写出 3 条可检验假设;
2. **补机制证据链**: 生理(体成分/心肺/炎症代谢) + 行为心理(自我效能/动机/执行功能) + 环境(供给结构/协同强度);
3. **设计升级**: 单点短周期 → 多中心 + 纵向 ≥3 时点 + 分层随机/阶梯楔形 + 中介与多层模型 + 剂量组;
4. **体量对齐**: 周期 3-4 年、样本 600-1000、经费按目标层级口径编制;
5. **创新重述 + 基础补强**: 由"模式/手册/过程评估"升级为"机制解释 + 规律 + 理论框架",并补机制类前期成果与团队配置。

**④ 输出要求**: 给出(a)定级结论与逐维打分表; (b)贯通性结论(应用链条/科学链条分别判定); (c)五步升级路线; (d)路径建议(维持现有形态投哪类 / 预研后升级 / 直接冲高),并注明改动量。

**约束**: 定级须**基于稿件实际内容**给出,不得为迎合用户而拔高; 指出不足时同步给出可操作的补强动作。

## 约束

- Plus 版**不改变**学校/类型的母版和格式规范,只增强内容深度
- Plus 版**同样走去AI味、标题构思、字数把控**等通用规则
- 审核返修时,保持段落逻辑顺序(总起→展开→结论),不因返修打乱结构
- 用户未明确要求时,**默认普通版**,不主动升级
- 数据支撑**只写真实可查证的数据,严禁编造**;用户提供的数据需优化后写入(统一单位/精度、科研化、嵌入逻辑),不照抄
